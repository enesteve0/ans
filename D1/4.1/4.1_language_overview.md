# 4.1 Language Overview

## Name

**ANS** — *Alchemist's Notation Script*

## Intended Domain

ANS is a small domain-specific language for declaring chemical elements, compounds, and reactions, verifying atomic balance at compile time, and performing stoichiometric queries such as molar mass and theoretical yield. It targets undergraduate chemistry students and instructors who want to express calculations the way they appear in textbooks rather than as bare numerical code.

## Sample Program

```ans
// Declare elements
element H {
    atomic_mass = 1.008,
    valence = 1,
    symbol = "H"
};
element O {
    atomic_mass = 15.999,
    valence = 2,
    symbol = "O"
};
element C {
    atomic_mass = 12.011,
    valence = 4,
    symbol = "C"
};

// Declare compounds
compound water {
    formula = H2O,
    name = "Water"
};
compound methane {
    formula = CH4,
    name = "Methane"
};
compound co2 {
    formula = CO2,
    name = "Carbon dioxide"
};
compound oxygen {
    formula = O2,
    name = "Oxygen"
};

// Declare variables
let num = 20;
let name = "Hydrogen";
let char = 'H';
let elements = [H, O, C];
let n = 21.2;
let compounds = [water, methane, co2, oxygen];

// Function declaration for computing yield of a compound in a reaction
function compute_yield(reaction r, compound c) {
    let products = r.products;
    let reactants = r.reactants;
    let reactant_mol = 1.0 / mol(reactants[c]);
    let product_mol = reactant_mol * mol(products[c]);
    return product_mol;
};

// Function declaration for computing molar mass of a compound
function molar_mass(compound c) {
    let formula = c.formula;
    let mass = 0.0;
    for (let element in formula) {
        mass += element.atomic_mass * formula[element];
    }
    return mass;
};

// Declare a reaction and verify it is balanced at compile time
reaction combustion {
    reactants = CH4 + 2*O2,
    products = CO2 + 2*H2O,
    check = balanced,
    energy = exothermic 890.3 kJ/mol
};

reaction combustion2 {
    reactants = methane + 2*oxygen,
    products = co2 + 2*water,
    check = balanced,
    energy = exothermic 890.3 kJ/mol
};

// Stoichiometric query
molar_mass(water);
compute_yield(combustion, CH4);

// if statements
if (compute_yield(combustion, 5.0 mol, CH4) > 0) {
    print "The yield of CH4 is positive, so combustion is possible.";
}
elif (compute_yield(combustion, 5.0 mol, CH4) == 0) {
    print "The yield of CH4 is zero, so combustion is not possible.";
}
else {
    print "The yield of CH4 is negative, so combustion is not possible.";
}
```

## Sebesta Language-Evaluation Criteria (Ch. 1)

Following Sebesta's Chapter 1 evaluation framework — **readability, writability, reliability**, and **cost** — ANS deliberately prioritises the first three while knowingly sacrificing the last along with generality and orthogonality.

**Readability** is prioritised because the syntax mirrors chemistry vocabulary directly (`element`, `compound`, `reaction`, `reactants`, `products`, `balanced`) over a familiar C-like skeleton (`let`, braces, semicolons, `if`/`elif`/`else`), so the meaning of a program can be inferred from its surface form without consulting a manual. Typed function parameters (`compound c`, `reaction r`) further document intent at the declaration site. **Writability** is prioritised because common domain tasks — declaring an element, writing a balanced equation as `CH4 + 2*O2`, or querying `molar_mass(water)` — are first-class constructs rather than user-coded library routines; the required `import std` line gives access to the full standard chemistry library in one token. **Reliability** is prioritised through compile-time validation: the lexer recognises formula literals (`H2O`, `CH4`) and unit literals (`mol`, `kJ/mol`) as distinct token categories, the semantic checker verifies that every element symbol exists and that every reaction with `check = balanced` has equal atom counts on both sides before any value is computed, and units are tracked rather than silently discarded.

The accepted trade-offs are the higher **implementation cost** of formula parsing, unit handling, and balance checking; the loss of **generality** (ANS is unsuited to non-chemistry tasks); and reduced **orthogonality**, since many fixed domain forms replace a small set of freely combinable primitives. Sebesta explicitly notes that language design is a process of selecting trade-offs among these criteria; for a teaching-oriented chemistry DSL the gains in domain-specific clarity and compile-time safety outweigh the loss of general-purpose expressiveness.
