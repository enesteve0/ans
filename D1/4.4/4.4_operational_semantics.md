# 4.4 Operational Semantics

Following Sebesta Section 3.5, ANS describes the meaning of non-trivial
constructs by explaining their effects on an abstract machine state. The state
contains the current environment, the runtime store, and the global chemistry
table of declared elements, compounds, reactions, and functions. This section
uses informal operational semantics: instead of formal inference rules, it shows
the lower-level steps taken by the semantic checker and interpreter.

The two main constructs described here are formula loops and balanced reaction
checking. Formula indexing, species lookup, reaction atom maps, and atom-map
equality are supporting operations used to define those two constructs.
Function-call behavior, including call-by-value parameter binding and
stack-dynamic function frames, is discussed in Section 4.6 with names, binding,
scope, and lifetime.

The descriptions use these helper operations:

```text
current_scope            the active lexical environment frame
evaluate(E)              evaluate expression E and return its value
execute(S)               execute statement or block S
new_scope(parent)        create a nested lexical scope frame
lookup(name)             find a name using static scope
type(V)                  return the runtime type of value V
semantic_error(M)        stop semantic checking with message M

parse_formula(F)         convert a formula literal to a formula value
formula_elements(F)      return formula symbols in left-to-right first-appearance order
formula_count(F, E)      return the numeric atom count of element E in formula F
species_formula(S)       return the formula value for a reaction species
reaction_atoms(R)        return the atom-count map for a reaction side
atom_maps_equal(A, B)    compare two atom maps, treating missing keys as 0
bind_reaction(N, R)      bind reaction object R to name N
```

A formula value stores both counts and iteration order:

```text
H2O  -> counts { H: 2, O: 1 }, order [H, O]
CH4  -> counts { C: 1, H: 4 }, order [C, H]
O2   -> counts { O: 2 },       order [O]
```

## 4.4.1 Formula Loop: `for (let element in formula)`

ANS uses formula loops to visit the distinct elements inside a formula:

```ans
for (let element in formula) {
    body
}
```

The expression after `in` is evaluated first. It must produce a formula value.
The loop visits each distinct element in the formula using the formula's stored
left-to-right first-appearance order, so the execution is deterministic. For
`H2O`, the body runs first for `H`, then for `O`.

Operational meaning:

```text
F = evaluate(formula)

if type(F) is not formula:
    semantic_error("for-in expression must be a formula")

L = formula_elements(F)

for each symbol S in L, from left to right:
    if S is not a declared element:
        semantic_error("formula uses undeclared element")

    iteration_scope = new_scope(current_scope)
    bind element in iteration_scope to the element object for S

    execute body using iteration_scope

    destroy iteration_scope
```

The loop variable is scoped only inside one loop iteration. A fresh nested scope
frame is created for every iteration, and declarations inside the body disappear
when that iteration frame is destroyed. If the body assigns to an outer variable,
normal static-scope assignment rules still apply, so that outer variable can be
updated. If an outer scope already has a variable with the same name as the loop
variable, the loop variable shadows it only inside the iteration scope.

Although normal formula literals are non-empty, a formula-valued expression could
evaluate to an empty formula value. In that case, `formula_elements(F)` returns
an empty list, the body executes zero times, and no loop variable is created.

Supporting operation: formula indexing.

The expression:

```ans
formula[element]
```

is a normal postfix indexing expression in ANS. When the left side is a formula,
the index must be an element:

```text
F = evaluate(formula)
E = evaluate(element)

if type(F) is not formula:
    semantic_error("left side of formula index must be a formula")

if type(E) is not element:
    semantic_error("formula index must be an element")

result = formula_count(F, E)
```

If the element does not occur in the formula, the result is `0`. The result is a
plain numeric count, so it can be used with numeric fields such as
`element.atomic_mass`. For example:

```ans
mass += element.atomic_mass * formula[element];
```

is executed as:

```text
count = formula_count(formula, element)
term  = element.atomic_mass * count
mass  = mass + term
```

This lets ANS express molar-mass calculations in chemistry-like syntax while the
interpreter still has a precise rule to follow.

## 4.4.2 Reaction Balance Check: `check = balanced`

The parser accepts a list of reaction fields by syntax, but the semantic phase
requires exactly one `reactants`, `products`, `check`, and `energy` field. A
missing field or duplicate field is a semantic error, not a syntax error.

Source construct:

```ans
reaction N {
    reactants = R,
    products = P,
    check = balanced,
    energy = D Q
};
```

Operational meaning:

```text
if N is already bound in the chemistry table:
    semantic_error("reaction name already declared")

if reactants, products, check, or energy is missing:
    semantic_error("reaction is missing a required field")

if any required field appears more than once:
    semantic_error("reaction has duplicate field")

if check is not balanced:
    semantic_error("reaction check must be balanced")

if D is not exothermic and is not endothermic:
    semantic_error("reaction energy must be exothermic or endothermic")

energy_direction = D
energy_value = evaluate(Q)

if type(energy_value) is not quantity:
    semantic_error("reaction energy must be a quantity")

if energy_value.unit is not kJ and is not kJ/mol:
    semantic_error("reaction energy unit must be kJ or kJ/mol")

left_atoms  = reaction_atoms(R)
right_atoms = reaction_atoms(P)

if atom_maps_equal(left_atoms, right_atoms) is false:
    semantic_error("reaction is not balanced")

reaction_value = Reaction(N, R, P, energy_direction, energy_value, balanced = true)
bind_reaction(N, reaction_value)
```

In the ANS semantic/interpreter phase, evaluating a reaction declaration performs
these checks before adding the reaction to the global chemistry table. The
`check = balanced` field does not automatically balance an equation. It requires
the programmer's written reaction to already conserve atoms.
Name, field, and energy errors are checked before atom-map construction, so
undeclared elements inside reaction sides are reported when `reaction_atoms` is
evaluated.

Supporting operation: species formulas.

Reaction species can be formula literals or compound names:

```text
species_formula(S):
    if S is a formula literal:
        return parse_formula(S)

    if S is an identifier:
        C = lookup(S)
        if C is a declared compound:
            return C.formula

    semantic_error("reaction species must be a formula literal or compound name")
```

For example, if `compound water { formula = H2O, name = "Water" };` has already
been declared, then `species_formula(water)` returns the formula value for
`H2O`. This allows reactions to use either direct chemistry notation like `H2O`
or named compounds like `water`.

Supporting operation: reaction atom maps.

A reaction side is reduced into a map from element symbols to total atom counts.
While building this map, every element symbol inside each species formula must
refer to a declared element; otherwise ANS raises `semantic_error("reaction uses
undeclared element")`.
Scalar multiplication on an atom map multiplies every count in the map. Addition
of atom maps merges their keys and sums counts, treating missing keys as `0`.
For example, `{ C: 1, H: 4 } + { O: 4 }` becomes `{ C: 1, H: 4, O: 4 }`, and
`2 * { O: 2 }` becomes `{ O: 4 }`.

For the reactant side:

```ans
CH4 + 2*O2
```

ANS computes:

```text
reaction_atoms(CH4 + 2*O2)
= 1 * parse_formula(CH4) + 2 * parse_formula(O2)
= { C: 1, H: 4, O: 4 }
```

For the product side:

```ans
CO2 + 2*H2O
```

ANS computes:

```text
reaction_atoms(CO2 + 2*H2O)
= 1 * parse_formula(CO2) + 2 * parse_formula(H2O)
= { C: 1, H: 4, O: 4 }
```

Supporting operation: atom-map equality.

Two atom maps are equal when every element has the same count on both sides.
Missing elements are treated as count `0`:

```text
atom_maps_equal(A, B):
    all_symbols = union(keys(A), keys(B))

    for each symbol S in all_symbols:
        left_count  = A[S], or 0 if missing
        right_count = B[S], or 0 if missing

        if left_count != right_count:
            return false

    return true
```

Therefore, the combustion reaction succeeds:

```ans
reaction combustion {
    reactants = CH4 + 2*O2,
    products = CO2 + 2*H2O,
    check = balanced,
    energy = exothermic 890.3 kJ/mol
};
```

because both sides produce `{ C: 1, H: 4, O: 4 }`.

An unbalanced reaction fails:

```ans
reaction bad_water {
    reactants = H2 + O2,
    products = H2O,
    check = balanced,
    energy = exothermic 0 kJ/mol
};
```

Here the reactants produce `{ H: 2, O: 2 }`, while the products produce
`{ H: 2, O: 1 }`. The oxygen counts differ, so ANS raises:

```text
semantic_error("reaction is not balanced")
```

This makes balanced reaction checking a reliability feature: chemically invalid
reactions are rejected before the reaction object becomes part of the program
state.
