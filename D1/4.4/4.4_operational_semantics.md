# 4.4 Operational Semantics

Following Sebesta Section 3.5, ANS describes the meaning of non-trivial
constructs by explaining their effects on an abstract machine state. The state
contains the current environment of variable bindings, the store of runtime
values, and a global chemistry table containing declared elements, compounds,
reactions, and functions. This style fits ANS because Part 2 adds semantic
checking and interpretation, so each construct can be explained as a sequence of
clear lower-level operations.

This section uses informal operational semantics. Instead of giving formal
inference rules, it explains how the interpreter evaluates a construct and how
the program state changes. The helper operations below are used in the
descriptions:

```text
evaluate(E)              evaluate expression E and return its value
type(V)                  return the runtime type of value V
formula_elements(F)      return the distinct element symbols in formula F
formula_count(F, S)      return the subscript count of symbol S in formula F
element_object(S)        return the declared element object for symbol S
species_formula(SP)      return the formula map for a formula literal or compound name
reaction_atoms(R)        return the total atom-count map of reaction side R
bind_reaction(N, R)      bind reaction object R to name N
semantic_error(M)        stop semantic checking with message M
```

## 4.4.1 Formula Iteration: `for (let element in formula)`

ANS supports the loop form:

```ans
for (let element in formula) {
    body
}
```

This construct is used in the molar-mass example to visit each element in a
compound formula. Its meaning is defined by translating the loop into simpler
operations over a normalized formula map.

Source construct:

```ans
for (let element in E) {
    B
}
```

Operational meaning:

```text
F = evaluate(E)

if type(F) != formula:
    semantic_error("for-in expression must be a formula")

L = formula_elements(F)
i = 0

loop_start:
    if i >= length(L) goto loop_end

    S = L[i]
    element = element_object(S)

    if element is undefined:
        semantic_error("formula uses undeclared element")

    execute B in a new nested scope where element is bound to element_object(S)

    i = i + 1
    goto loop_start

loop_end:
    discard loop variable element
```

The expression after `in` must evaluate to a formula value. A formula value is
represented internally as a map from element symbols to atom counts:

```text
H2O  becomes  { H: 2, O: 1 }
CH4  becomes  { C: 1, H: 4 }
O2   becomes  { O: 2 }
```

Therefore, the loop iterates once for each distinct element symbol in the
formula, not once for each atom. For `H2O`, the body executes twice: once with
`element` bound to the element object `H`, and once with `element` bound to the
element object `O`.

The related indexing operation used inside the loop has this operational
meaning:

```ans
formula[element]
```

```text
F = evaluate(formula)
E = evaluate(element)

if type(F) != formula:
    semantic_error("left side of formula index must be a formula")

if type(E) != element:
    semantic_error("formula index must be an element")

result = formula_count(F, E.symbol)
```

So the ANS statement:

```ans
mass += element.atomic_mass * formula[element];
```

is interpreted as:

```text
count = formula_count(formula, element.symbol)
term  = element.atomic_mass * count
mass  = mass + term
```

This rule keeps the source code readable for chemistry users while giving the
interpreter a precise execution behavior.

## 4.4.2 Reaction Balance Check: `check = balanced`

ANS reactions have fields for `reactants`, `products`, `check`, and `energy`.
The grammar treats `check = balanced` as a reaction field. Reaction terms use
either a species by itself or an explicit coefficient followed by `*`, such as
`2*O2`.

Source construct:

```ans
reaction N {
    reactants = R,
    products = P,
    check = balanced,
    energy = E
};
```

Operational meaning:

```text
left_atoms  = reaction_atoms(R)
right_atoms = reaction_atoms(P)

if left_atoms != right_atoms:
    semantic_error("reaction is not balanced")

energy_value = evaluate(E)

reaction_value = Reaction(
    name = N,
    reactants = R,
    products = P,
    energy = energy_value,
    balanced = true
)

bind_reaction(N, reaction_value)
```

The helper operation `reaction_atoms` reduces each reaction side to an
atom-count map. For example, the reactant side:

```ans
CH4 + 2*O2
```

expands as:

```text
M = empty atom map

term CH4:
    coefficient = 1
    F = species_formula(CH4)
    add 1 * F to M

term 2*O2:
    coefficient = 2
    F = species_formula(O2)
    add 2 * F to M

return M
```

So:

```text
reaction_atoms(CH4 + 2*O2)
= { C: 1, H: 4 } + 2 * { O: 2 }
= { C: 1, H: 4, O: 4 }
```

For the product side:

```ans
CO2 + 2*H2O
```

the expansion is:

```text
reaction_atoms(CO2 + 2*H2O)
= { C: 1, O: 2 } + 2 * { H: 2, O: 1 }
= { C: 1, H: 4, O: 4 }
```

Because the two atom-count maps are equal, this reaction succeeds:

```ans
reaction combustion {
    reactants = CH4 + 2*O2,
    products = CO2 + 2*H2O,
    check = balanced,
    energy = exothermic 890.3 kJ/mol
};
```

An unbalanced reaction fails during semantic checking. For example:

```ans
reaction bad_water {
    reactants = H2 + O2,
    products = H2O,
    check = balanced,
    energy = exothermic 0 kJ/mol
};
```

has this operational result:

```text
reaction_atoms(H2 + O2) = { H: 2, O: 2 }
reaction_atoms(H2O)     = { H: 2, O: 1 }
```

Since the oxygen counts are different, the abstract machine raises:

```text
semantic_error("reaction is not balanced")
```

This explains the design purpose of `check = balanced`: it is not an instruction
to automatically balance the equation. It is a semantic constraint requiring the
programmer's reaction to already conserve atoms. In ANS, this improves
reliability because a chemically invalid reaction is rejected before the
reaction object is added to the program state.
